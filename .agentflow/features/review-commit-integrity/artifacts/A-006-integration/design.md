# Read-only evaluation integration

Owner approved the previously presented integration flow with "那可以開始接上了". Build a standalone bridge script beside the released evaluator, keeping version0.1.0 immutable. Existing authenticated findings/audit GET endpoints supply source data; no new Rust API or persistent server. Exact repo/PR/session/head/base scope is operator supplied and recorded, never replaced by current PR head. Use existing hardened source packet and input validators. Preserve raw capture, hashes, excluded findings and partial coverage. Ledger title is the available claim text, explicitly labelled title-only. Source evidence is independently captured from immutable Git source, not model claims. Optional product snapshot can provide existing weekly tables; absent tables remain unknown. No fabricated completeness, human truth, actual cost or review authority.

Normal journey: capture bounded paginated audit and findings for exact PR/session, prepare normalized findings/evidence from fixed Git revision, run existing evaluator with explicit model/environment files and auth, invoke existing weekly reporter with verified evaluation. New/empty external directories only; retries must not overwrite prior captures. Remote credentials are read from environment and never serialized or forwarded to models. Only HTTPS with no redirects for observation secrets; local test server allowed only explicitly.

Added concepts: capture metadata is necessary to bind remote records to run scope and expose endpoint truncation; preparation report is necessary to expose stale/malformed findings without silently scoring them. Rejected smaller alternative: parsing GitHub prose would lose stored finding identity and source scope. Rejected larger alternative: new exporter API, queue, service, scheduler and package release are unnecessary to prove first integration.

Tests: failing integration journey, pagination/truncation, mismatched SHA/session, empty/malformed/duplicate findings, unsafe paths and output collisions, no credential persistence, real local HTTP PTY capture/prepare and actual remote read-only pilot. Existing96-test suite remains relevant.
